# Avenger 설계문서

> 기준일: 2026-11-02 · 기준 진행도: T1 ~ T9 완료 (2주차 진행 중)
> 기능 명세는 `개발문서.md`, 이 문서는 **코드가 어떻게 짜여 있는지**를 설명한다.
> 아직 구현되지 않은 부분은 *(예정)* 으로 표시한다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 2D 사이드뷰 액션 로그라이크 |
| 핵심 | 적의 예고 공격을 0.15초 패링으로 받아치는 반격 전투 |
| 엔진 | pico2d (SDL2 래퍼) · 2DGP 수업 프레임워크 구조 |
| 화면 | 1280 × 720 고정, 방 단위 화면 (스크롤 없음) |
| 그래픽 | 현재 전부 도형(`draw_rectangle`). 에셋은 T19에서 교체 |

### 설계 원칙

1. **수치는 `config.py`에만** 둔다. 객체 코드에는 로직만 남긴다.
2. **시간 기반**: 모든 이동·타이머는 `game_framework.frame_time`(초)을 사용한다. 프레임 수로 세지 않는다.
3. **모듈 = 싱글턴**: 모드와 시스템(hitstop, camera 등)은 클래스가 아니라 모듈 전역 상태로 둔다 (2DGP 수업 방식).
4. **데이터 주도**: 방 배치는 JSON, 적 공격은 `Attack` 데이터 객체로 정의한다.

## 4. 프레임워크

### 4.1 game_framework — 모드 스택과 메인 루프

모드 모듈은 `init / finish / update / draw / handle_events / pause / resume` 7개 함수를 가진다.

| 함수 | 동작 |
|---|---|
| `change_mode(m)` | 맨 위 모드 `finish` 후 교체, `m.init()` |
| `push_mode(m)` | 맨 위 모드 `pause`, `m`을 위에 쌓고 `init` (일시정지·강화 선택용) |
| `pop_mode()` | 맨 위 모드 `finish`, 아래 모드 `resume` |
| `quit()` | 루프 종료 플래그 |

메인 루프 (`run`):

```
while running:
    stack[-1].handle_events()
    stack[-1].update()
    stack[-1].draw()
    frame_time = min(now - prev, MAX_FRAME_TIME)   # 첫 프레임 폭주 방지 (0.05s)
```

### 4.2 game_world — 객체 관리

- **레이어**: `world[depth]` 리스트 6개. 앞 레이어부터 update/render.

  | depth | 상수 | 내용 |
  |---|---|---|
  | 0 | `DEPTH_BG` | 배경 |
  | 1 | `DEPTH_MAP` | 지형·발판·문 |
  | 2 | `DEPTH_ENEMY` | 적·투사체 |
  | 3 | `DEPTH_PLAYER` | 플레이어 |
  | 4 | `DEPTH_EFFECT` | 섬광·파티클 |
  | 5 | `DEPTH_UI` | HUD *(예정)* |

- **지연 제거**: `remove_object`는 `_pending_removal`에 모으기만 하고, `update()` / `update_layer()` / `handle_collisions()` 끝에서 한꺼번에 제거한다. 순회 중 리스트 변경을 막기 위함.
- **충돌 쌍**: `add_collision_pair(group, a, b)` → `handle_collisions()`가 AABB 겹침 시 양쪽 `handle_collision(group, other)` 호출. 현재 전투 판정은 `systems/combat.py`가 직접 처리하므로 투사체(T10~)부터 사용할 예정.
- `show_hitbox`: F1로 토글되는 디버그 플래그. 각 객체가 `draw()`에서 확인한다.

### 4.3 객체 인터페이스

| 메서드 | 필수 | 설명 |
|---|---|---|
| `update()` | O | `game_framework.frame_time`으로 갱신 |
| `draw()` | O | |
| `get_bb() -> (l, b, r, t)` | O | 몸 hitbox |
| `handle_collision(group, other)` | O | 충돌 쌍 콜백 (없으면 `pass`) |
| `handle_event(e)` | 플레이어만 | |
| `get_attack_bb() -> (l, b, r, t) \| None` | 공격 주체 | 공격 판정 구간에서만 사각형 반환 |

## 5. play_mode — 한 프레임의 처리 순서

```
handle_events()
  ├─ SDL_QUIT / Esc → quit        (Esc는 T20에서 push_mode(pause_mode))
  ├─ F1 → show_hitbox 토글
  └─ 그 외 → player.handle_event(e)   ← 히트스톱 중에도 받아 선입력 버퍼에 저장

update()
  1. stopped = hitstop.is_active()      ← 타이머를 줄이기 전에 판단
  2. hitstop.update(dt), camera.update(dt)
  3. stopped면 → 이펙트 레이어만 update 하고 return
  4. game_world.update()                ← 모든 객체 이동·상태 갱신
  5. combat.resolve(player, enemies)    ← 공격 판정
  6. game_world.handle_collisions()
  7. 죽은 적을 enemies 목록에서 제거

draw()
  배경 사각형 → camera.begin() → game_world.render() → camera.end() → update_canvas()
```

`play_mode`가 보유하는 상태: `player`, `room`, `enemies`. 런 상태(`run_state`: 방 순서, 강화 목록, 통계)는 T13에서 추가한다.

## 6. 좌표계와 지형 충돌 (`systems/terrain.py`)

- 원점은 좌하단, y 위쪽 증가.
- 캐릭터의 `(x, y)`는 **발 중심**. 몸 hitbox = `(x - w/2, y, x + w/2, y + h)`.
- `Platform(x, y, w, h, kind)`의 `(x, y)`는 **좌하단**. `kind`는 `'solid'` 또는 `'oneway'`.

이동은 항상 다음 순서로 분리한다.

```
x += vx * dt  →  terrain.resolve_x()  →  화면 좌우 clamp
vy += GRAVITY * dt
y += vy * dt  →  terrain.resolve_y()  →  (y, vy, on_ground)
```

| 함수 | 규칙 |
|---|---|
| `resolve_x` | solid만 검사. 겹치면 블록 **중심 기준 가까운 쪽**으로 밀어냄 (벽 끼임 방지) |
| `resolve_y` 착지 | `vy <= 0`이고 `prev_y >= top`, `y <= top` → solid·oneway 모두 착지. 이동 전후 구간으로 판정해 고속 낙하 시 얇은 발판 관통 방지 |
| `resolve_y` 머리 | solid만. 상승 중 머리가 바닥면을 넘으면 막음. oneway는 아래에서 통과 |

## 7. 플레이어 (`objects/player.py`)

### 7.1 상태 표현

개발문서의 상태(`Idle, Run, Jump, Attack1~3, Parry, ParryStun, Dash, Hit, Dead`)를 별도 상태 클래스 대신 **독립 타이머 + 판정 함수**로 표현한다. 동작끼리 캔슬·선입력이 많아서 타이머 조합이 더 단순하기 때문이다.

| 상태 | 판정 | 타이머 / 플래그 |
|---|---|---|
| Dash | `is_dashing()` | `dash_timer`, `dash_cooldown` |
| Attack1~3 | `is_attacking()` | `attack_timer`, `attack_step`(1~3), `combo_timer` |
| Parry | `is_parrying()` | `parry_timer`, `parry_success`, `parry_cooldown` |
| ParryStun | `is_parry_stunned()` | `parry_stun_timer` |
| Hit | `is_hit()` | `hit_timer`, `hit_dir` |
| 무적 | `is_invincible()` | 대시 중 · `invincible_timer` · 사망 |
| Jump / 공중 | `not on_ground` | `vy`, `jump_held` |
| Dead | `dead` | |

- `is_busy()`: 공격·대시·피격·패링·경직 중 하나라도 해당 → 새 공격·점프를 바로 시작하지 않고 선입력.
- `can_parry()`: 쿨타임 0이고 대시·피격·패링·경직이 아닐 때. **공격 중이어도 가능**(캔슬).

### 7.2 update 우선순위 (이동 결정)

```
사망 / 패링 경직   → 정지
피격 경직          → hit_dir 방향으로 PLAYER_HIT_KNOCKBACK 속도로 밀림
대시               → DASH_DIST / DASH_TIME 속도, 중력 무시. 마지막 프레임은 남은 시간만큼만 이동
공격·패링 중       → 지상은 제자리, 공중은 이동 유지 (방향 고정)
그 외              → 좌우 입력대로 이동, 방향 전환
```

### 7.3 입력

| 키 | 처리 |
|---|---|
| ← → | 누름 상태(`left_pressed`, `right_pressed`)를 따로 저장. `move = right - left` |
| Alt | 지상·비busy면 `vy = JUMP_SPEED`. 상승 중 떼면 `vy *= JUMP_CUT` (가변 점프) |
| A | busy면 `attack_buffer = INPUT_BUFFER`, 아니면 `start_attack()` |
| S | `can_parry()`면 `start_parry()`, 아니면 `parry_buffer = INPUT_BUFFER` |
| Space | `start_dash()` — 공격 캔슬, 콤보 초기화 |

### 7.4 공격 3연타

```
start_attack: attack_step = (step % 3) + 1, attack_timer = STARTUP + ACTIVE + RECOVER
   │
   ├─ elapsed ∈ [STARTUP, STARTUP + ACTIVE) 동안 get_attack_bb()가 사각형 반환
   │
   └─ attack_timer 종료 → combo_timer = COMBO_WINDOW
          ├─ 그 안에 A(또는 버퍼) → 다음 타
          └─ 만료 → attack_step = 0 (콤보 끊김)
```

- 한 번 휘두를 때 같은 적은 한 번만 맞는다 (`attack_hits` 집합).
- 3타는 `ATTACK3_KNOCKBACK` 넉백.

## 8. 적 (`objects/enemy_base.py`)

### 8.1 Attack 데이터

```python
Attack(name, parryable, telegraph, windup, active, recover, damage, hitbox)
```

- `telegraph`는 생성 시 `max(telegraph, TELEGRAPH_MIN)`으로 보정된다.
- `hitbox`는 `(가로, 세로)`, 몸 앞쪽(바라보는 방향)에 붙는다.

### 8.2 상태 머신

```
          감지 거리 안
  Idle ───────────────▶ Chase ◀─────────────────────────────┐
                          │ 사거리 안 & 쿨타임 0               │
                          ▼                                  │
     ┌──────────────▶ Telegraph ─▶ Windup ─▶ Active ─▶ Recover
     │  (attack_queue에                                       │
     │   남은 공격 있음) ◀──────────────────────────────────────┤
     │                                                       │ 큐 비었음 → 쿨타임 설정
     │                                                       ▼
     │                                                     Chase
  어느 상태든 패링당함 → Stagger (ENEMY_STAGGER_TIME) → Chase
  HP ≤ 0 → Dead (remove_object + 처치 연출)
```

- `choose_attacks()`: 서브클래스가 이번에 쓸 `Attack` 목록(연타면 여러 개)을 반환 → `attack_queue`.
- `on_parried()`: 남은 연타 취소, 공격 쿨타임 설정, Stagger 진입.
- `take_damage(damage, knockback)`: Stagger 중이면 `× STAGGER_DAMAGE_MULT`. 넉백은 `KNOCKBACK_TIME`에 나눠 밀어냄.
- 이동·중력·지형 충돌은 플레이어와 같은 `terrain` 함수를 쓴다.

### 8.3 시각 표현 (도형)

| 상황 | 표시 |
|---|---|
| Telegraph | 몸이 `TELEGRAPH_BLINK` 주기로 흰색(패링 가능) / 빨간색(불가) 번쩍임 |
| 패링 불가 Telegraph | 머리 위 빨간 `!` |
| Windup | 몸 뒤쪽 위로 무기를 든 막대 |
| Active | 공격 hitbox를 주황색으로 채움 |
| 피해 | `ENEMY_HURT_FLASH` 동안 밝은 색 |
| Stagger | 노란색 |

### 8.4 서브클래스

| 클래스 | 상태 | 공격 |
|---|---|---|
| `EnemyMelee` | 구현 | `slash1` → `slash2` 2연타 (둘 다 패링 가능, 2타는 짧은 예고) |
| 방패 돌진 | *(T12)* | `parryable=False`, `shield_rush_chance` 확률로 선택 |
| `EnemyFlyer`, `EnemyArcher` | *(T10)* | 급강하 / 화살 투사체 |
| 보스 2종 | *(T17, T18)* | `EnemyBase` 확장 + posture·그로기·패턴 가중치 |

## 9. 전투 판정 (`systems/combat.py`)

`combat.resolve(player, enemies)`를 매 프레임 월드 update 직후 호출한다.

```
[플레이어 → 적]
  attack_bb = player.get_attack_bb()
  겹친 적 중 이번 휘두름에 아직 안 맞은 적 → e.take_damage(피해, 방향 × 넉백)

[적 → 플레이어]
  e.get_attack_bb()가 몸과 겹치고 e.attack_hit == False일 때
    ├─ player.is_parrying() and e.attack.parryable
    │     → 패링 성공: e.attack_hit = True
    │                  player.on_parry_success(e)   (쿨타임 0)
    │                  e.on_parried()               (Stagger)
    │                  effect.parry_success(접촉점)  (히트스톱·흔들림·섬광·불꽃)
    └─ 그 외
          → e.attack_hit = player.take_hit(피해, e.x)
            피해가 들어갔으면 effect.player_hit()
            (무적이라 무시됐으면 Active가 남은 동안 다시 검사)
```

- **패링이 무적보다 우선**: 피격 무적 중이라도 패링 판정 중이면 성공 처리한다 (대시 중에는 패링을 시작할 수 없음).
- 패링 판정 시간(`PARRY_WINDOW`)은 성공해도 끝까지 유지 → 동시에 들어온 여러 공격도 막는다.
- 판정 시간 동안 아무것도 막지 못하면 `PARRY_FAIL_STUN` 경직. 경직 중 피격은 `× STUN_DAMAGE_MULT`.
- *(T11)* 투사체는 `game_world` 충돌 쌍으로 처리하고, 패링 시 방향 반전 + 소유자 변경.

## 10. 연출 시스템

### 10.1 히트스톱 (`systems/hitstop.py`)

- 전역 `timer` 하나. `start(d)`는 `max(timer, d)` — 더 긴 히트스톱이 걸려 있으면 유지.
- 히트스톱 중 `play_mode`는 이펙트 레이어만 갱신하고 카메라 흔들림도 계속 진행한다.
- *(T17)* 슬로모션: 월드에 `frame_time × 배율`을 전달하는 방식으로 확장.

### 10.2 화면 흔들림 (`systems/camera.py`)

- `shake(amp, time)`: 현재 남은 세기보다 셀 때만 덮어씀.
- 세기는 남은 시간에 비례해 선형 감소.
- `begin()`에서 `SDL_RenderSetViewport`로 viewport를 `(0 ~ 2·amp)` 범위 랜덤 오프셋만큼 옮겨 월드 전체를 흔들고, `end()`에서 원상복구. (SDL viewport가 음수 위치를 잘라내므로 양수 범위 사용)

## 11. 방 시스템 (`systems/room.py`)

### 11.1 템플릿 형식 (`data/rooms/<name>.json`)

```json
{
  "name": "platform_01",
  "type": "발판형",
  "platforms": [[x, y, w, h, "solid|oneway"], ...],
  "spawn_sets": [[["melee", x, y], ...], [...]],
  "player_start": [x, y],
  "door": [x, y]
}
```

- `Room(name)`: JSON을 읽어 `Platform` 목록, 스폰 정보, 시작 위치, 문 위치를 보관.
- `spawn_sets`: 적 배치 세트 목록. 방을 만들 때 하나를 무작위로 고른다. 세트가 하나면 `"spawns": [...]`로 써도 된다.
- 일반 템플릿 6종: `flat_01`(평지형) · `platform_01/02`(발판형) · `canyon_01/02`(협곡형) · `mixed_01`(혼합형). 각 2세트.
- `spawn_enemies(player)`: `ENEMY_TYPES` 딕셔너리(`'melee' → EnemyMelee`)로 이름을 클래스에 매핑해 생성. 새 적은 이 딕셔너리에 등록만 하면 JSON에서 쓸 수 있다.
- 경로는 `os.path.dirname(__file__)` 기준이라 실행 위치와 무관하다.

### 11.2 런 진행

```
전투1 → 강화① → 전투2 → 전투3 → 중간보스 → 강화② → 전투4 → 최종보스 → 클리어
```

- 방 진입 시 문 잠금 → 적 전멸 → 문 개방 → 문 접촉 시 다음 방.
- 같은 런에서 템플릿 중복 금지: `play_mode.init()`에서 `random.sample(ROOM_TEMPLATES, RUN_COMBAT_ROOMS)`로 이번 런의 방 순서(`run_rooms`)를 정한다.
- 사망 시 런 상태 전체 초기화.

## 12. config.py 구성

| 섹션 | 주요 항목 |
|---|---|
| 화면 | `SCREEN_W/H`, `GRAVITY`, `MAX_FRAME_TIME` |
| 레이어 | `DEPTH_*`, `LAYER_COUNT` |
| 폰트·색 | `FONT_PATH`, `COLOR_TEXT*`, `COLOR_PLAY_BG` |
| 플레이어 | 이동·점프·대시·공격 단계별 시간(`ATTACK_STARTUP/ACTIVE/RECOVER`)·hitbox 크기·색 |
| 디버그 | `COLOR_DEBUG_BODY/ATTACK` |
| 지형·방 | `COLOR_SOLID/ONEWAY`, `TEST_ROOM` |
| 패링 | `PARRY_WINDOW`, `PARRY_COOLDOWN`, `PARRY_FAIL_STUN`, 각종 배율·히트스톱 시간 |
| 연출 | 흔들림 세기·시간, 섬광 색·알파·시간, 파티클 스펙(dict) |
| 예고 | `TELEGRAPH_MIN`, `COLOR_PARRYABLE/UNPARRYABLE`, `TELEGRAPH_BLINK` |
| 적 | 적 종류별 스탯 `dict` (`MELEE`, `FLYER`, `ARCHER`) — 크기·색·사거리·공격 단계 시간 포함 |
| 보스·진행 | `POSTURE_MAX`, `GROGGY_*`, `BOSS_*`, `UPGRADE_CHOICES` |

적 스탯을 `dict`로 묶어 두면 `EnemyBase.__init__(..., stats, ...)`가 공통 키(`hp, speed, w, h, color, detect_range, attack_range, attack_cooldown`)를 읽고, 서브클래스는 공격 관련 키만 따로 읽는다.
